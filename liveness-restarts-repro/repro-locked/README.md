# Phase-locked reproducer (v2) — constant period & amplitude, Prow-faithful load

Self-contained bundle, structurally identical to `../repro/` (same manifest
names and scripts) but with a **phase-locked** load: constant oscillation
period, constant storm amplitude, and a phase-locked kill window every cycle.
**Do not mix the two stacks in one namespace** — run one bundle at a time.

## Layout

| File | Purpose |
|---|---|
| `run.sh` | one-command deployment: TLS cert, namespace + SCC, configmaps, workloads, verification |
| `watch.sh` | streams liveness-kill events, flags cascades |
| `teardown.sh` | deletes the namespace (all workloads, configmaps, RBAC) |
| `manifests/00-namespace.yaml` | the `haproxy-repro` namespace |
| `manifests/10-configmaps.yaml` | healthz + router config plumbing |
| `manifests/20-haproxy-victim.yaml` | the probed kill target: haproxy (frontends 8080/8443/8444 + `monitor-uri` 1936) + nginx backend (2936 plain / 2937 TLS, 1 KB page), hostNetwork, Recreate strategy |
| `manifests/30-victims.yaml` | 15 idle low-weight probed victims (cascade breadth) |
| `manifests/40-scenario-client.yaml` | **7 phase-locked wrk clients** (calibrated to the real Prow run's load) |
| `manifests/50-restarter.yaml` | **phase-locked restart amplifier** (one rollout restart per 380 s cycle at mark 365, with a sub-second re-fire guard) |
| `files/haproxy.cfg` | the router config (frontends + backends) |
| `files/1024.html` | the 1 KB response page |
| `tls.pem` | self-signed cert (regenerated by `run.sh` if absent) |

## Design

Same pure-traffic shape as `../repro/` (everything co-located on one 4-vCPU
worker), with two changes:

1. **Wall-clock phase-locked clients** (`manifests/40-scenario-client.yaml`):
   every phase start is aligned to the global grid (`unix epoch mod 380`)
   instead of free-running shell loops. All replicas land their transitions on
   the exact 190 s marks forever and self-correct after any wrk overrun —
   so the connection storms superimpose constructively every cycle:
   - **constant period**: two storms per 380 s cycle, on the 0/190 marks
   - **constant amplitude**: the same 3500-handshake burst every cycle
   Grid: edge occupies [0,180), passthrough [190,370).
2. **Phase-locked restarter** (`manifests/50-restarter.yaml`): fires at mark
   365 of every 380 s cycle — 15 s before the edge start — so the new haproxy
   pod's bind race + rebuild storm coincides with the clients' pt→edge
   teardown/rebuild storm (the maximum-pressure moment) at the same point of
   every cycle. A 20 s guard sleep after each trigger prevents sub-second
   re-fires (`sleep_to` returns 0 if the trigger command completes inside the
   same grid second — observed as 4 back-to-back rollout restarts before the
   guard was added).

## Deployment

```sh
export KUBECONFIG=/tmp/kubeconfig
NODE_NAME=<kubernetes.io/hostname> NODE_IP=<node IP> ./run.sh
# in another terminal:
NS=haproxy-repro KUBECONFIG=$KUBECONFIG ./watch.sh
```

The phase lock is wall-clock based, so **scaling is seamless**: new pods wait
for the next grid boundary and join in phase (`oc scale` at any time).

## Calibration (validated 2026-10-14, `211.64.1.el10_2`, node `ip-10-0-20-108`)

| Clients | Connections/storm | load1 max | load1 trough | Notes |
|---|---|---|---|---|
| 10 × `-c500` | 5000 | ~50 (max 54) | ~11 | deeper than the real workload |
| 6 × `-c500` | 3000 | ~25 | ~10 | slightly under |
| **7 × `-c500`** | **3500** | **~27** | **~12.6** | **matches the real Prow run (max 29.1, mean 12.4)** |

**7 clients is the calibrated default** — the load signature matches a real
Prow ingress-perf run (load1 max 29.1 / mean 12.4). Real-node CPU at this
level: **386% of 4 cores non-idle** (system 169%, user 157%, softirq 56%,
idle 3.5%) — the Prow job's 398% peak is the same state; the residual idle is
the 10 s teardown gaps, part of the oscillation itself.

## Validated behavior

- Restarter triggers at mark 365–366 of every cycle (379–381 s apart) — one
  rollout restart per 380 s cycle, confirmed 3/3.
- **Kills continue at the Prow-faithful load level** (load1 max ~27, runnable
  ~27): 19 liveness kills in the 40-min verification watch.
- **The kill events are phase-locked to the grid**: mapped to `epoch mod 380`,
  the kill clusters repeat at mark ~214–230 (the pt-phase storm window) every
  ~380 s (intervals 381 / 379 / 378 / 368 s — 5 clusters), plus the
  restarter-triggered cluster at marks 367–378 (2 s after the mark-365
  trigger). Constant period, constant amplitude, kills riding the same phase
  of every cycle.
- **Three-kernel matrix (same node, same recipe):**
  | Kernel | Lineage | Result |
  |---|---|---|
  | `6.12.0-211.64.1.el10_2` | EEVDF + reweight exposure | 19 kills / 40 min |
  | `5.14.0-687.57.1.el9_8` | CFS (pre-EEVDF) | **0 kills / 40 min, 0 restarts** |
  | `6.12.0-55.30.1.el10_0` | pre-regression, wakeup bug present | **16 kills in ~7 min** — violent, as with the simple variant (74/15 min) |
- **Fresh-cluster A/B re-validation (2026-10-15, `ci-rosa-s-89av`, plain
  worker `ip-10-0-12-166`, same node both sides):** stock
  `211.64.1.el10_2` → **18 kills / ~24 min**, a kill cluster 30–46 s into
  **4/4 consecutive pt phases** (marks 220–236, cycle starts 379/383/384 s
  apart); then `687.57.1.el9_8` (CFS, via
  `quay.io/mcornea/rhel-coreos-10:5.14.0-687.57.1`) → **0 kills / 40 min,
  0 restarts** at identical load (load1 23 vs 22.5, CPU 114% both). The
  bundle is portable as-is and the falsification holds on a fresh cluster.
- The dashboard's "Workers CPU Usage" = `sum(rate(node_cpu_seconds_total{
  mode!="idle"}))×100`; node-exporter `instance` labels are node *names*
  (`ip-10-0-x-y.us-west-2.compute.internal`).
